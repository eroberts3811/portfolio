# Portfolio website brief

## About me
I'm a product designer, [Your Name]. This is my personal portfolio site.
I'm not a developer, so please write all the code, explain decisions in
plain language, and keep the setup as simple as possible.

## Goal
Show my work to [recruiters / hiring managers / clients]. Visitors should
understand who I am and see my best projects within the first few seconds.

## Tech preferences
- Use [plain HTML/CSS/JS | Astro | your recommendation based on the structure below].
- Static site only, no backend.
- Minimal dependencies, and nothing I'll need to maintain heavily.
- Hosting: GitHub repo, deployed via [Netlify | Vercel]. Please set up the
  repo and walk me through connecting the deployment and my custom domain
  ([yourdomain.com]).

## Sitemap
- Home: intro + selected projects grid
- Case studies: [3-5] pages, one per project
- About: bio, skills, experience, photo
- Contact: email, LinkedIn, [other links]

## Design direction
- Vibe: [e.g. minimal, editorial, warm, playful, bold]
- Typography: [fonts, or "suggest a pairing that fits the vibe"]
- Colors: [hex codes, or describe the palette]
- Layout notes: [e.g. generous whitespace, large imagery, grid-based]
- Interactions: [e.g. subtle hover states, smooth page transitions, none]
- References I like: [links to sites you admire, and what you like about each]
- My mockups are in the /design folder. Follow them closely.

## Case study structure
Each case study should be easy to add. [If Astro: write each as a
Markdown file with front matter for title, role, timeline, cover image.
If plain HTML: create one reusable template page.]
Typical sections: overview, problem, process, solution, outcome.

## Requirements
- Fully responsive (mobile, tablet, desktop), designing mobile-first.
- Accessible: semantic HTML, good color contrast, alt text, keyboard
  navigation, visible focus states.
- Fast: optimized images (WebP/AVIF with sensible sizes), lazy loading,
  no unnecessary scripts.
- SEO basics: page titles, meta descriptions, Open Graph image for
  link previews, favicon.
- Keep content (text, project data, image paths) separate from layout so
  I can update it easily.

## How to work with me
1. Start by reading this brief and my mockups, then propose a short plan
   and the file structure. Wait for my approval before building.
2. Build the homepage first and let me review it before the other pages.
3. I'll give feedback in plain language (e.g. "more spacing", "subtler
   hover"). Make the changes without asking me to edit code.
4. Use placeholder content where I haven't supplied any, and list what
   you need from me (copy, images, links).
